# UX削減会議

## 目的

介護職員が「確認待ちを開く → 内容を確認する → 記録を確定する」を迷わず終えられることを最優先にする。表示要素は、現在の判断に必要か、記録の安全性と根拠確認に必要なものだけにする。

## ページごとの主操作

| ページ   | 主操作                                        |
| -------- | --------------------------------------------- |
| 確認待ち | `確認する`                                    |
| 録音確認 | `記録を確定`                                  |
| 確定後   | `次の確認へ`                                  |
| 入居者   | 未確認があれば `確認する`、なければ記録を読む |
| 申し送り | `申し送りを作成`                              |

## 段階表示へ移す情報

- 元の会話全文
- 項目ごとの根拠発言
- 記録しない会話
- 過去の記録と変更履歴
- 技術情報、監査情報、デモ用操作

## 維持する情報

- 入居者の明示的な紐付け
- AI候補の個別編集・除外
- 根拠発言への到達手段
- 確定前の確認と確認者の記録
- 介護記録、プロフィール、申し送りの成果物

## 検証方法

- 確認待ちから確定までの画面遷移数と主要ボタン数を数える
- 各ページに強い主操作が1つだけ表示されることを確認する
- デスクトップと390px幅で同じ次の行動が理解できることを確認する
- 根拠、履歴、監査情報へ必要時に到達できることを確認する
- 確定後の修正率と、確認1件あたりの所要時間を追う

### 次に検討する家族向け報告

家族向け報告は職員間の「申し送り」と用途・閲覧者が異なるため、別の入居者単位の作成画面とする。確定済みの当該入居者の情報だけを候補にし、職員へ「ご家族に伝えたいことはありますか」と尋ね、文面を編集・確認してから送る。公式LINE連携は宛先、送信権限、同意、認証情報、送信履歴の要件が決まってから接続する。現時点では自動送信や他の入居者の情報を混ぜる実装は採用しない。
