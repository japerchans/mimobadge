# こころん（MimoBadge）

こころんは、介護中に生まれる会話を、消えていく情報ではなく施設全体で使える「共有知識」に変えるWebアプリです。確認済みの会話から、入居者一人ひとりの生活歴・好み・人間関係・最近の様子・ケア上の注意点をメモリーブレインへ蓄積し、介護士の記録、入居者への理解、家族への近況共有につなげます。

会話が増えるほど理解が深まり、その理解がより良い会話とケアを生む循環を施設全体につくることを目指しています。

**このリポジトリの入居者・職員・デモ会話は架空です。OpenAI APIキーを設定すると、SDカードや端末内の音声ファイルを取り込んで文字起こしできます。**

## 起動

Node.js 20.9以降が必要です。

```sh
npm install
npm run dev
```

[ローカル画面](http://127.0.0.1:3000)を開きます。設定なしの開発環境では、架空の入居者5人・職員3人を用意し、`.data/workspace.json` に変更を保存します。ページの更新やサーバーの再起動でもデータは残ります。このファイル保存は単一の開発サーバー専用です。

## 使い方

1. 「会話を取り込む」で、SDカードから複数の録音ファイルをドラッグ＆ドロップします。大きいWAVはブラウザ内で自動分割し、最大200MBまで1件の会話として取り込めます。
2. 録音冒頭の「〇〇さんです」から入居者を自動判定し、文字起こしと情報整理を行います。判定できない場合だけ職員が選択します。
3. 元の会話と、介護記録・プロフィールの候補を照合します。介護記録は F-SOAIP（着眼点・本人の言葉・観察・判断・介入・計画）で整理され、血圧・体温・食事量などは数値欄にも表示されます。
4. 内容を編集し、不要な項目を「記録から除外」します。
5. 「確認して共有知識に反映」で確定します。
6. 確認済み情報は介護記録、入居者のメモリーブレイン、家族レポートの下書きへ反映されます。
7. 「申し送り」と「家族レポート」で、同じ確認済み情報から共有文面を作れます。

デモ録音は「設定・利用情報」から追加できます。

手入力した下書きは、候補の編集で勝手に上書きしません。必要なら「選択内容から作り直す」を押し、確定前に文章を確認してください。

## 画面の考え方

入口では録音の取り込みと確認待ちの会話だけを扱います。入居者を選ぶと、「この方について」で確認済み情報とメモリーブレインから大事な情報を短く確認できます。介護記録、申し送り、家族レポートは同じ共有知識から作り、名前検索は入居者一覧で使えます。

画面ごとの役割と操作の理由は [DESIGN.md](DESIGN.md) にまとめています。

## 技術構成

- Next.js 16 / TypeScript / App Router
- PostgreSQL（`pg` によるパラメーター付きSQL）
- 録音処理・音声保存・入居者関連付けの差し替え用インターフェース
- 独立した情報整理モジュール `MnemoNet`
- 承認済み情報から作る自伝的記憶グラフ（人物・場所・出来事・時期）
- 確定前の候補と確定済みの情報を分離
- 施設単位のアクセス境界、更新履歴、承認トランザクション

| ディレクトリ  | 役割                                           |
| ------------- | ---------------------------------------------- |
| `app/`        | ページ、ログイン、API                          |
| `components/` | 一覧、入居者画面、録音確認、出典編集などのUI   |
| `domain/`     | 情報の抽出・分類・承認・履歴統合・申し送り     |
| `services/`   | 音声処理と非公開ストレージのインターフェース   |
| `db/`         | PostgreSQLスキーマ、保存処理、架空の初期データ |
| `lib/`        | 認証、日本語表記                               |
| `tests/`      | ワークフローとデータベースの検証               |

1録音を1会話として扱う小さな構成です。話者の発言と候補は録音に属し、介護イベントとプロフィールは種別を持つ共通テーブルに保存します。施設・入居者・出典録音の関係は外部キーで管理し、細部は型付きJSONBに保持します。

### Memory Brain API

`GET /api/memory-graph/:residentId` は、ログイン中の施設に属する入居者について、承認済みプロフィールから作った記憶グラフを返します。ノードは人物・場所・出来事・時期の4種類です。同じ録音で確認されたノードを共起エッジで結び、各エッジは共起回数と出典エピソードを保持します。

レスポンスにはノード・エッジ・エピソードのほか、研究で扱うノード数、最大連結成分、平均次数、ノード種類の多様性を含みます。これらは研究用の構造指標であり、診断や臨床評価を返すAPIではありません。プロフィールの編集・削除時はグラフ全体を承認済み情報から再構築するため、古い関係が残りません。

## PostgreSQLで動かす

Dockerが利用できる場合は付属の設定でPostgreSQLを起動できます。既存のPostgreSQLでも構いません。

```sh
docker compose up -d
export DATABASE_URL='postgresql://mimo:mimo@localhost:5432/mimobadge'
npm run db:migrate
```

マイグレーションは新規施設にだけ架空の初期データを投入します。既存データは初期化しません。

`.env.example` を `.env.local` にコピーし、次を設定します。

- `DATABASE_URL`：PostgreSQL接続先
- `SESSION_SECRET`：32文字以上のランダムな秘密値
- `DEMO_ACCESS_CODE`：プロトタイプ用の共通アクセスコード
- `OPENAI_API_KEY`：入居者AIチャットとSDカード音声の文字起こしに使うサーバー側APIキー
- `OPENAI_CHAT_MODEL`：入居者AIチャットと記録候補の抽出に使うモデル
- `OPENAI_TRANSCRIBE_MODEL`：音声ファイルの文字起こしに使うモデル
- `APP_ORIGIN`：リバースプロキシを使う場合の公開HTTPSオリジン

マイグレーションはシェルの環境変数を参照します。Next.jsの `.env.local` は自動では読み込みません。

```sh
npm run build
npm start
```

本番モードではPostgreSQLとログイン設定が必要です。未設定の場合、ローカルデータ保存へ自動で切り替えません。

## データと確認の境界

- 候補は職員が確定するまで入居者情報に入りません。
- 除外した候補は入居者情報に反映されません。手入力の記録本文も職員が確認します。
- 承認はトランザクション内で実行し、同じ承認の再送で重複を作りません。
- 編集前の版と更新日時を照合し、別画面での更新を上書きしないようにします。
- 会話の全文は確定時、または7日経過後の次回アクセス時に削除します。
- 確認済みの短い出典とプロフィールの変更履歴は残ります。
- 現在のプロフィールを削除しても、過去に確定した記録と保存済みの申し送りは書き換えません。
- 操作ログには介護内容を複製しません。
- 施設IDはリクエスト本文ではなくサーバー側セッションから取得します。

## 介護記録の形式

介護記録は、厚生労働省の介護分野における生産性向上の手引きで紹介されている項目形式の記録法を参考にしています。F-SOAIPの6項目に分けることで、本人・家族の言葉、職員が観察した事実、評価、実施したケア、次の対応を区別します。定型的な食事量、水分量、排泄、バイタルは数値・定型欄でも確認できます。

これは施設ごとの法定様式や運用規程を置き換えるものではありません。実運用では、施設が定める必須項目、事故・服薬・身体拘束等の個別帳票、保存期間に合わせて調整してください。

- [厚生労働省：介護分野における生産性向上の取組](https://www.mhlw.go.jp/kaigoseisansei/tool/index.html)
- [介護事業所・介護施設における項目形式の介護記録法の導入マニュアル（PDF）](https://www.jmar.co.jp/asset/pdf/job/public/llgr2_155_manual.pdf)

## デモの範囲と今後の接続

実際の音声解析、長時間録音からの会話分割、個人別アカウント、定期削除ジョブ、耐久性のある処理キュー、暗号鍵管理、バックアップ、外部監査ログなどは実運用前に必要です。共通アクセスコードは個人別認証の代わりにはなりません。

録音の保存先は非公開ストレージを想定し、`public/` には置きません。現在のSDカード取り込みはアップロードした音声をその場で文字起こしし、会話全文と確認候補だけを確認待ちに追加します。デモ転送はサンプル会話を使います。

## 検証

```sh
npm run typecheck
npm test
npm run build
```

承認、除外、プロフィール統合、重複防止、競合更新、施設境界、入居者の手動設定、保存期限、申し送り、日本語表記を検証します。PostgreSQLのスキーマ検証には埋め込み版PostgreSQLのPGliteを使用します。

起動中のアプリに対する追加確認：

```sh
node tests/smoke.mjs
```

この確認は架空の録音と申し送りを1件作成します。
